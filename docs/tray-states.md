# トレイの操作と段階

見張りの観測の順番待ちは、段階を変えない（観測を飛ばすだけ）。

通常停止は最初のawait前に停止処理／終了処理を確保する。上げ待ちで拒否された窓には拒否結果の件数と理由を渡し、不明なら「件数は確認できません」と示す。待つ／戻るの直後に監視が生きているかを確認し、終了済みなら状態の読取りから自分の起動の終了を確認する。生きた子が残る場合だけ、同じControlGate内で持ち主PID・開始時刻、世代ID・番号、子PID・開始時刻を照合し、自分の物を通常停止する。別入口の準備・子へは停止や取消しを出さず、自分の段階を停止済みとして既存の知らせと状態の窓で案内する。待機後の自動停止も同じ照合を通す。確認失敗は停止失敗／終了失敗。強制は窓で明示した場合だけ。

準備の取消しは、受付後に完了・停止番号の保存が失敗しても再試行へ進めない。受付より先に準備の保存が失敗した場合も、あとから完了・停止番号の保存に成功しても、その失敗を知らせる。通信・子の起動だけの失敗の後の取消しは正常に終える。後片づけの保存も失敗した場合は、取消しと元の理由を保ち、その失敗を併記する。保存失敗を知らせ、状態と回復の記録を残す。Windows終了の確認は同じ設定の上げ待ちを確認するため従来の通常停止を使う。
状態・起動準備・回復記録の読取りや保存が失敗した見張りは、初回再試行・自動再起動をやめて知らせる。保存先を確認し、再開・start・run の明示操作でやり直す。通信だけの失敗の再試行は続ける。

監視が生きている間は子の予期しない終了で最大3回起動し直す。上限到達・監視終了では表の再確認へ進む。自動で起動し直せず非0で終わった場合の知らせは、試した回数を断定せず、設定とログの確認とメニューの「再開」を促す。初回起動の成否は後片づけ後にその起動だけが確定する。停止成功後の安全確認が失敗しても前段階に戻さない。設定変更と接続窓終了は設定の再読取り・後片づけを終えてから停止済みとし、元が見張り中なら再開する。ログアウトは停止済み。確定した接続も新しく起動する。
