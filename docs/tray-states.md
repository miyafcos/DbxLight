# トレイの操作と段階

受付はResidentContext.Phaseで決め、Snapshotは表示用。設定等は設定適用・権限・接続・ログアウト。Windows終了列は安全を確認できず保留した場合。表は同じ常駐内の受付を示し、独立CLIはCoreの排他で処理する。

| 起動中 | 準備取消し＋通常停止 | 準備取消し＋通常停止 | 拒否 | 表示のみ | 通常停止 | 後片づけ後に自分の世代を確認 |

見張りの観測の順番待ちは、段階を変えない（観測を飛ばすだけ）。

通常停止は最初のawait前に停止処理／終了処理を確保する。上げ待ちで拒否された窓には拒否結果の件数と理由を渡し、不明なら「件数は確認できません」と示す。待つ／戻るの直後に監視が生きているかを確認し、終了済みなら状態の読取りから自分の起動の終了を確認する。生きた子が残る場合だけ、同じControlGate内で持ち主PID・開始時刻、世代ID・番号、子PID・開始時刻を照合し、自分の物を通常停止する。別入口の準備・子へは停止や取消しを出さず、自分の段階を停止済みとして既存の知らせと状態の窓で案内する。待機後の自動停止も同じ照合を通す。確認失敗は停止失敗／終了失敗。強制は窓で明示した場合だけ。

準備の取消しは、受付後に完了・停止番号の保存が失敗しても再試行へ進めない。受付より先に準備の保存が失敗した場合も、あとから完了・停止番号の保存に成功しても、その失敗を知らせる。通信・子の起動だけの失敗の後の取消しは正常に終える。後片づけの保存も失敗した場合は、取消しと元の理由を保ち、その失敗を併記する。保存失敗を知らせ、状態と回復の記録を残す。Windows終了の確認は同じ設定の上げ待ちを確認するため従来の通常停止を使う。
状態・起動準備・回復記録の読取りや保存が失敗した見張りは、初回再試行・自動再起動をやめて知らせる。保存先を確認し、再開・start・run の明示操作でやり直す。通信だけの失敗の再試行は続ける。

監視が生きている間は子の予期しない終了で最大3回起動し直す。上限到達・監視終了では表の再確認へ進む。自動で起動し直せず非0で終わった場合の知らせは、試した回数を断定せず、設定とログの確認とメニューの「再開」を促す。初回起動の成否は後片づけ後にその起動だけが確定する。停止成功後の安全確認が失敗しても前段階に戻さない。設定変更と接続窓終了は設定の再読取り・後片づけを終えてから停止済みとし、元が見張り中なら再開する。ログアウトは停止済み。確定した接続も新しく起動する。

止める確認の画面が出ているあいだも停止処理・終了処理の段階なので、ほかの道具による busy も通知しない。

手動の更新確認と更新開始は、見張り中または停止済みで受け付ける。ダウンロード中の重複した更新は受け付けない。
監視中の更新予約は通常の終了と同じ停止処理を通る。更新時の強制停止は無効にし、自分の監視・世代・子プロセスを照合して、通常停止が Clean で回復不要と確認できた場合だけ、新しい CLI を切り離して起動する。
停止済みでは、一時停止の受領を必要とせず、同じ設定の Clean な停止記録と記録したプロセスの終了、または記録が一つもないことを ControlGate 内で確認する。ダウンロード前と最終停止時に確認する。
状態不明、停止後の記録の変化、監視終了、別プロセスの動作で更新を始められない場合は、停止済みの常駐と有効な「再開」メニューを残す。題「更新できませんでした」、本文「マウントの状態を確認できなかったため、更新を始めませんでした。トレイのメニューからマウントを再開し、状態を確かめてから、もう一度お試しください。」を1回通知し、不要な staging を片づける。別プロセスの動作に関する既存の通知と状態表示も保つ。
待機を取り消した場合は、監視が生きていれば監視中に戻り、終了済みなら停止済みに留まる。更新失敗の通知を出さない。停止自体が失敗した場合は既存の「停止できません」を出す。強制停止・Windows 終了・Dispose では予約を取り消すだけにする。
swap を起動できない場合は更新予約を取り消し、停止済みの常駐を残す。更新を始められずマウントが停止したままであることを知らせ、メニューから再開できる。
設定画面の updateCheck だけを変える保存は、通常停止と再開を通らずに設定と確認タイマーへ反映する。自動起動やほかの項目を一緒に変える場合は、既存の停止・保存・再開を通す。
