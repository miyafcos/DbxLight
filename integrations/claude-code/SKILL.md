# DbxLight のマウント先を扱うとき
見本のマウント先は T:。実際のドライブと権限は dbxl agent-guide で確認する。

- フォルダの中身を再帰で検索しない。先に dbxl ls / dbxl find で候補を絞り、必要な1件だけを開く。
- ls / find / stat / refresh / resolve は内容をダウンロードせず調べる用途に使う。rg や grep にマウント先全体を渡さない。
- ファイルを閉じてから wait を呼び、待っている間に同じファイルを保存し直さない。0 は中身の一致までは保証しない。 保存したら dbxl wait <パス> --json を呼び、終了値0を確認してから「保存した」と報告する。wait が 0 以外なら、Dropbox 上へアップロードされたことを確認できていないと報告し、ローカルの保存を保つ。
- busy は未確認（成功でも失敗でもない）。数秒おいて同じコマンドを呼び直す。
- 見えるはずのファイルが無ければ、無いと言う前に dbxl refresh <フォルダ> --json をして再度見る。
- 読み取り専用では新しく保存できない。保存先をローカルの別の場所にするか、人に知らせる。前からローカルに残る未アップロードのファイルが送信されることはある。
- 表示しないフォルダは通常の一覧・検索で見えない。必要なら人に知らせ、AI が自分で設定を変えない。
- recoveryRequired / processUncertain、または未確認の状態が返ったら人に知らせ、AI が自分で回復を解除しない。 退避したファイルは dbxl rescue list --json で理由と保存先を確認して人へ伝える。必要な内容は利用者が保存先からドライブの元の場所へ戻す。名前によっては自動で再アップロードせず退避する。くわしくは docs/cli.md。
- このアプリは、公式の Dropbox アプリのような競合コピーを作りません。ほかの人と同じファイルを同じ時間帯に直すと、あとから保存した側の内容で上書きになり、先に保存した人の変更が失われることがあります。 保存したファイルは、少し遅れて Dropbox 上へアップロードされます。アップロードされるまでの時間は、件数と大きさで変わります。 前回止めたときに未アップロードだったファイルだけは、起動の直前 (30 秒以内) に Dropbox 上の状態と比べ、変わっていないファイルだけをアップロードします。変わっていたファイルや問題のあるファイルは、ローカルに退避して残し、自動では戻しません。保存先で中身を確かめ、Dropbox 上と見比べてから、必要な内容を自分で戻してください。 公式の Dropbox アプリと、同じフォルダへ同時に書き込まないでください。
- 停止・再接続・設定変更・強制操作・回復解除のコマンドは、人に頼まれたときだけ使う。
- 稼働中の一覧・検索・stat は全角の記号も Windows が見せる名前のまま返す。返った path を使う。フォルダの size / modifiedUtc が null なら未取得。0バイトや仮の日時として扱わない。
- skippedUnsafe>0 は安全でない名前を省いた件数。そのフォルダで「無い」と断言せず、人に知らせる。
- truncated=true は continuation の案内に従う（offset があれば --offset）。depthLimited=true は必要なパスへ絞って深さを増やす。timeLimited=true なら同じ引数に continuation.offset の --offset を付けて続け、範囲が分かるなら --in で絞る。

| コマンド | 道具の使い分け |
| --- | --- |
| dbxl ls "T:\資料" --json | 開く前に1階層の一覧（既定1000件） |
| dbxl find "原稿" --in "資料" --json | 内容を読まず名前から探す（既定深さ8・1000件） |
| dbxl stat "資料/原稿.txt" --json | 大きさ・時刻・キャッシュ・アップロードの状態 |
| dbxl wait "T:\資料\原稿.txt" --json / dbxl wait --all --json | 保存後の Dropbox 上との照合 |
| dbxl refresh "資料" --json | 外から届いたファイルが見えないとき |
| dbxl resolve "資料/原稿.txt" --json | ローカル・相対パス・Web URL の対応 |
| dbxl agent-guide / dbxl status --json | 現在のガイド / 状態 |

| 終了値 | 新コマンドの意味 |
| --- | --- |
| 0 | 成功。wait は Dropbox 上を照合済み |
| 2 | 使い方の誤り |
| 3 | まだ・時間切れ・未確認・回復未完了・プロセス不明 |
| 4 | 処理・アップロードの失敗 |
| 5 | 読み取り専用で新しく保存できない |
| 6 | 動いていない |
既存コマンドの通常失敗は1、アップロード待ちの拒否は3。status は終了値だけで判断せず、JSON の ok・recoveryRequired・processUncertain も読む。全コマンドの仕様は docs/cli.md。ひな形はリポジトリ内に置き、PC の道具の設定へ自動で入れない。
